# Требования к серверу для развёртывания PD-Proxy

## Обзор

PD-Proxy — модуль безопасности персональных данных с двухуровневой архитектурой:
- **Regex-эшелон** — детекция ПДн регулярными выражениями (21 категория)
- **FastJev-эшелон** — локальный LLM-классификатор (Qwen3-0.6B, llama.cpp) для anti-FP

Модуль работает **полностью на CPU**, GPU не требуется.

---

## Конфигурации серверов

### 1. Минимальная (только Regex, `mode=fast`)

| Параметр | Значение |
|----------|----------|
| **CPU** | 2 vCPU |
| **RAM** | 2 ГБ |
| **Диск** | 10 ГБ SSD |
| **ОС** | Ubuntu 22.04 LTS / Debian 12 |
| **Сеть** | 100 Мбит/с |

**Когда подходит:**
- Демонстрация / хакатон
- Низкая нагрузка (до 3000 RPS)
- FastJev отключён (`PD_PROXY_JEV_ENABLED=false`)

**Ожидаемая производительность:**
- RPS: 3000–5000 (x86), до 9000 (ARM/Apple Silicon)
- p99 latency: < 50 мс

---

### 2. Рекомендуемая (полный режим, `mode=full` с FastJev)

| Параметр | Значение |
|----------|----------|
| **CPU** | 4 vCPU |
| **RAM** | 4 ГБ |
| **Диск** | 15 ГБ SSD |
| **ОС** | Ubuntu 22.04 LTS / Debian 12 |
| **Сеть** | 100 Мбит/с |

**Когда подходит:**
- Боевое развёртывание с anti-FP фильтрацией
- Средняя нагрузка (до 1000–2000 RPS в полном режиме)
- Один инстанс приложения

**Ожидаемая производительность:**
- RPS: 1000–2000 (зависит от доли запросов с FP-кандидатами)
- p99 latency: < 100 мс
- Inference Qwen3-0.6B: 5–15 мс на запрос (batch)

---

### 3. Продакшн / высокая нагрузка

| Параметр | Значение |
|----------|----------|
| **CPU** | 8 vCPU |
| **RAM** | 8 ГБ |
| **Диск** | 30 ГБ SSD |
| **ОС** | Ubuntu 22.04 LTS / Debian 12 |
| **Сеть** | 1 Гбит/с |

**Когда подходит:**
- Высоконагруженный сервис (> 2000 RPS)
- Несколько gunicorn-воркеров (4–8)
- Запас под логирование, мониторинг, ротацию данных

**Ожидаемая производительность:**
- RPS: 5000+ (4 воркера, линейное масштабирование)
- p99 latency: < 50 мс

## Потребление ресурсов (детализация)

### Оперативная память

| Компонент | Потребление |
|-----------|------------|
| ОС (Ubuntu minimal) | ~300 МБ |
| Python + FastAPI + gunicorn (1 воркер) | ~150 МБ |
| Модель Qwen3-0.6B (GGUF Q8_0) | ~700 МБ |
| In-memory хранилище маппингов (100K записей) | ~200 МБ |
| Запас | ~200 МБ |
| **Итого (1 воркер, FastJev вкл.)** | **~1.5 ГБ** |
| **Итого (4 воркера, FastJev вкл.)** | **~3.5 ГБ** |

> ⚠️ Модель загружается один раз при старте (Singleton). Каждый gunicorn-воркер загружает свою копию модели в память (~700 МБ × N воркеров). При 4+ воркерах рекомендуется ≥ 8 ГБ RAM.

### Дисковое пространство

| Компонент | Размер |
|-----------|--------|
| ОС + базовые пакеты | ~3 ГБ |
| Docker Engine | ~500 МБ |
| Docker-образ pd-proxy | ~500 МБ |
| Модель Qwen3-0.6B (GGUF) | ~639 МБ |
| Python-зависимости (в образе) | ~200 МБ |
| Логи (ротация) | ~1 ГБ |
| Запас | ~5 ГБ |
| **Итого** | **~10–15 ГБ** |

### CPU

| Режим | Нагрузка на CPU |
|-------|----------------|
| `mode=fast` (только regex) | Низкая (~5–10% на 1000 RPS) |
| `mode=full` (regex + FastJev) | Средняя (~30–50% на 4 vCPU при 1000 RPS) |
| Пиковая (100K-токен payload) | Высокая (до 100% на 1 ядро, кратковременно) |

## Сетевые требования

| Порт | Протокол | Назначение |
|------|----------|------------|
| 8080 | TCP (HTTP) | API pd-proxy |
| 443 | TCP (HTTPS) | Исходящий — к LLM API (если используется `/proxy`) |

- Входящий: только порт 8080 (или за reverse proxy на 80/443)
- Исходящий: требуется только при использовании `/proxy` эндпоинта (обращение к внешнему LLM API)
- В режиме `mode=fast` / `mode=full` без `/proxy` — **исходящий доступ в интернет не требуется**

## Быстрый старт развёртывания

```bash
# 1. Клонировать / распаковать проект
unzip pd-proxy.zip && cd pd-proxy

# 2. Запуск через Docker Compose
docker compose up -d

# 3. Проверка
curl http://localhost:8080/health
# {"status":"ok","version":"0.1.0"}

# 4. Тест маскирования
curl -X POST http://localhost:8080/process \
  -H "Content-Type: application/json" \
  -d '{"payload": "Иванов Иван, паспорт 4510 123456", "payload_id": "test-1"}'
```

## Масштабирование

### Вертикальное

Увеличение CPU/RAM на одном сервере + увеличение `workers` в `gunicorn.conf.py`:

```python
# gunicorn.conf.py
workers = 4  # по числу vCPU
```

### Горизонтальное

Несколько инстансов за балансировщиком (nginx / HAProxy):

```
┌─────────┐     ┌──────────────┐
│  nginx   │────▶│ pd-proxy #1  │
│ (LB)     │────▶│ pd-proxy #2  │
│          │────▶│ pd-proxy #3  │
└─────────┘     └──────────────┘
```

> ⚠️ При горизонтальном масштабировании необходимо заменить `InMemoryStorage` на Redis / PostgreSQL для общего хранилища маппингов между инстансами.
